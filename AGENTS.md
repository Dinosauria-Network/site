## Repo conventions (hand-written — edit freely)

### Environment & npm scripts
- npm scripts do **not** load `.env`. Anything needing env vars must run as `NODE_OPTIONS="-r dotenv/config" npx tsx scripts/<file>.ts` (the value **must be quoted** — bare `NODE_OPTIONS=-r dotenv/config npx ...` is parsed by sh as a nonexistent `dotenv/config` command).
- Real secrets live in `.env` (gitignored): `DATABASE_URL` (Supabase transaction pooler), `JEVSTYLE_API_KEY`. The plain `SUPABASE_URL` / `SUPABASE_ANON_KEY` / `SUPABASE_SERVICE_ROLE_KEY` are placeholders; the `NEXT_PUBLIC_SUPABASE_*` values are real. Server-side auth is deferred on purpose (see docs/phase-status.md).
- Sign of a missing-env failure: Drizzle `password authentication failed` or the Jev-Style test printing "No JEVSTYLE_API_KEY set — skipping live test".

### Script entrypoints (names ≠ filenames)
- The `ingest:*`, `editorial:*`, `source:health`, `retraction:check` scripts point at **existing** files; the originally-named files (`scripts/editorial-generate.ts` etc.) were never created and don't exist anywhere in git history.
- Map: `ingest:europe-pmc`/`ingest:arxiv` → `scripts/ingest-db.ts --adapter <name>` (no flag = all five; `ingest:crossref` stays on `scripts/ingest-crossref.ts`, which also records `paper_sources`), `ingest:journals` → `ingest-db.ts --adapter crossref-journals` (watched-journal latest sweep), `ingest:rss` → `ingest-db.ts --adapter rss` (non-journal outlets: Burke Museum, Archosaur Musings, SVPOW, Sauropoda blogspot, Tetrapod Zoology, Scientific American, NSF, USGS, NCYT — feed items enter `research_papers` as `peerReviewStatus='unknown'` and are scored by Jev-Style at ingest like everything else), `ingest:check` → `scripts/run-ingestion.ts` (discover() smoke test, read-only), `editorial:generate`/`editorial:classify` → `scripts/classify-and-prune.ts`, `editorial:retry`/`source:health`/`retraction:check` → `scripts/test-jev-style.ts`, `editorial:status` → `scripts/status.ts`. Actual logic: adapters in `lib/ingestion/`, classifier in `lib/ai/jev-style.ts`.
- **Crossref date window (since 2026-11):** the keyword sweep now filters on deposit date (`from-created-date`) instead of paging the whole corpus. Default window = last 3 days; `--since YYYY-MM-DD` (also `YYYY` / `YYYY-MM` accepted) narrows it, `--since all` disables the filter and walks the full corpus (one-off, slow). The `SourceAdapter.discover()` signature is `discover(cursor?, fromDate?, toDate?)`; `parseSinceArg(argv, defaultDays)` in `lib/ingestion/crossref-adapter.ts` is the shared parser. Other adapters ignore the extra args. Batch size is 100 rows (was 20) with `sort=published desc`, so a daily run typically makes 1–2 API calls.
- `lib/ingestion/crossref-adapter.ts` is the only Crossref keyword adapter; `lib/ingestion/crossref-journals.ts` is the watched-journals adapter (20 ISSN-verified journals — Cretaceous Research 0195-6671, J. Vert. Paleont. 0272-4634, Historical Biology 0891-2963 plus the user's full monitored journal list, added 2026-11 — latest 10 each, sorted newest-first, deduped by DOI). Both share `normalizeCrossrefRecord`. `lib/ingestion/rss.ts` fetches the nine non-journal outlets' feeds (XML via `rss-parser`, failures isolated per outlet); feed items land in `research_papers` with `peerReviewStatus='unknown'`, journalName=outlet, no DOI (dedup by title). Ingest dedup happens **before** the per-adapter `--limit` cap (default 5 new/run), so re-runs ratchet through new issues instead of re-importing duplicates.
- Abstracts: Crossref deposits **no abstract** for many Elsevier/T&F articles (verified for the watched journals). Ingest enriches missing abstracts via the multi-provider resolver (`lib/ingestion/abstracts.ts` → OpenAlex → Crossref → Semantic Scholar → Elsevier Abstract Retrieval API using `ELSEVIER_API_KEY`, free providers first, first hit wins; `lib/ingestion/openalex.ts` is now a thin wrapper). Outcomes are typed — `found` / `not-deposited` / `publisher-access-unavailable` / `error` — and non-found outcomes persist to `research_papers.metadata.abstractStatus`/`abstractAttempts`, so an Elsevier 401/403 is never reported as an ordinary missing abstract. Existing rows: `npm run backfill:abstracts` fills missing abstracts and rewrites draft descriptions that hold the headline fallback (human-edited/non-headline deks are never touched). `--dry-run` supported; summary prints `filled/not-deposited/publisher-access-unavailable/error`.
- **Destructive:** `classify-and-prune.ts` only scores `editorial_score IS NULL` papers, newest first, and only deletes below-threshold papers (default 0.25) when `--prune` is passed — a paper linked to any story is never deleted. `npm run editorial:generate` is dry-run by default — no silent deletes.

### Styles: legacy CSS + SCSS modules (duplication is intentional)
- `public/css/main.css` is legacy, intentionally de-minified for readability; it's being slowly migrated to SCSS modules (`components/`, `app/styles/`). Don't re-minify it; don't "dedupe" across the two systems.
- SCSS: use `@use "..."` with file path, not `@import` (see `app/styles/globals.scss`).
- The main content column (`.wrap.container`) gets a right-side reserve via `@media (width >= 1280px)` (240px) and `@media (width >= 1600px)` (25%) to make room for the fixed navigation rail; the hamburger toggle hides at ≥1280px. New layout rules go in modules, but verify against legacy selectors first — both apply at runtime.

### Editorial Phase 4 CLI (review surface — no admin UI)
- `npm run editorial:propose` — score papers **persisted in `research_papers.editorial_score`** (written by `editorial:classify`), create `draft` stories (≥ `--min-score`, default 0.5), issues next numeric postId = `max(DB body.sourcePostId, JSON max id) + 1`. Only papers published on/after `--since` are eligible — default `2024-01-01`; accepts `YYYY`, `YYYY-MM`, `YYYY-MM-DD`, or `--since all` to disable (papers with NULL `publication_date` are skipped while a filter is active). Older classics can still be proposed with an explicit flag, e.g. `--since 1975`. `--doi ABC,def` targets specific DOIs directly (bypasses the score/since filters). Excerpts are tag-stripped sentence-bounded prefixes of the abstract (never raw JATS); licence hints (EPMC `isOpenAccess` / Crossref `license[]`) are recorded in `media_assets`/body when known — never blocking. Since 2026-11 it also runs the Tier-2 image pass (below) before giving up on an image. Erratum-type papers (title starts with Correction/Erratum/Corrigendum/Errata/Addendum/"Note added…") are never proposed, however high their score.
- **Image auto-attach (Tier 2, since 2026-11):** when a proposed paper still has no image after the `og:image` attempt, `scripts/propose.ts` calls `lib/images/commons.ts` — a conservative Commons matcher. It only attaches when a taxon token detected in the title (genus from a "Genus species" pair, else first non-stoplist capitalized token — pure place/era/geo/common-word titles return nothing) matches a file title via exact token/alias, licence is CC BY / CC BY-SA (no NC/ND — the pipeline center-crops), CC0 or Public domain, width ≥ 1200 px; ranked paleo-context-first then by width. Anything else stays imageless. Every Tier-2 attach records `media_assets` with `reuseStatus='pending_verification'` and story `body.imageAutoMatch`/`imageAutoSource`; the human flips pending → verified and publishes explicitly. Licence flips are never automated and auto-verify is never set.
- `research_papers.publication_date` is persisted at ingest (since 2026-11); pre-existing rows were backfilled from OpenAlex (13/13 recovered). Do not insert papers without dates — treat NULL dates as a bug to fix, not to work around.
- `npm run editorial:pending` — list draft (`--all` includes `pending_review`; `--json` for raw). Per-story licence line pulled from `media_assets`; ends with a dedicated **NEEDS IMAGE** list of imageless drafts and the attach command.
- `npm run editorial:status` — one-shot corpus summary (papers, unscored count, stories by status, imageless drafts, media asset reuse status). Read-only.
- `npm run editorial:attach-image -- --slug <slug> --url <url-or-path>` — real images only (Wikimedia Commons CC images work; DOI pages typically 403 to scrapers so `og:image` is usually MISSING at propose time). Cap 5 MB, writes `public/images/news/<slug>.<ext>`, records `media_assets` (`reuseStatus='pending_verification'`, or `'verified'` for known CC licences), sharp-validates local files **before** anything lands in `public/`, auto-crops to 1024×633 (1.618:1 — ArticleCard box, see `lib/image-derivatives.ts` `CARD_RATIO`) and generates `-1024/-640/-480.jpg` derivatives at the same ratio. The same pipeline is available per-story from the admin editor's Image panel (`lib/admin/images.ts` → `attachStoryImage`, URL or file upload; admin-only, refuses svg/non-images/>5 MB/private hosts), plus `clearStoryImage` for dead references.
- News images must be 1024×633 (1.618:1, center-cropped): every pipeline write goes through `normalizeCardImage`, which center-crops the base before resizing — do not store raw off-ratio files in `public/images/news/`.
- `npm run editorial:publish -- <slug> [--date YYYY-MM-DD | --use-paper-date]` — hard-refuses without an existing on-disk image **or a non-empty description** (no placeholders, ever); sets `status='published'` + `publication_events` row (`metadata.publishedAtOverride` recorded when a date was forced). `--use-paper-date` stamps `publishedAt` from the paper's `publication_date`, clamped to today (an article can't be "published" before it exists).
- `npm run editorial:autopublish [--dry-run] [--min-score N]` — the daily-cron publish gate. Publishes a draft only when ALL hold: Jev-Style score ≥ `--min-score` (default **0.75**), non-empty description, image attached, matching `media_assets` row with machine-known CC licence (CC BY / CC BY-SA incl. NC/ND-free variants, CC0, Public domain — Commons extmetadata OK; publisher og:image with no recorded licence is NOT eligible), and not erratum-type. Everything else stays draft with a printed reason. Never flips `media_assets.reuseStatus` (machine licence ≠ human verification). Every publish writes `publication_events` with `metadata.autoPublished=true`. `--dry-run` prints the same report without writing.
- `npm run editorial:unpublish -- <slug>` — escape hatch for the auto-publish gate: published → back to draft, `published_at` cleared, `publication_events` row (`eventType='unpublished'`). Image and `media_assets` are left untouched.
- `.github/workflows/news.yml` — daily cron (06:15 UTC, `workflow_dispatch` also supported, **never on push**): `ingest:rss → ingest:journals → ingest:europe-pmc → ingest:crossref → editorial:classify → editorial:propose → editorial:autopublish → editorial:status`, then a pinned "News pipeline digest" GitHub Issue (create-or-comment) with the gate/status logs. Secrets needed: `DATABASE_URL`, `JEVSTYLE_API_KEY`, `ELSEVIER_API_KEY`. **Writes to the same production DB the site serves** — enabling the workflow is the user's call (push + secrets). News pages are ISR (`revalidate = 3600`), so auto-published stories appear within the hour.
- `npm run editorial:reject -- <slug>` — sets `status='rejected'`.
- One story per paper: unique `stories_paper_unique` on `editorial_stories.paper_id` (0003); `research_papers.doi` is unique (0004). `drizzle-kit push` is TTY-interactive here — apply SQL manually with `pg.Pool` via tsx (raw `.sql` files in `drizzle/`), not via `push`/`generate`.
- Admin/review UI is **deferred** until server-side auth lands (Phase 1b → Phase 5). The CLI is the review surface until then; do not build an admin UI in the meantime.

### Previewing drafts in dev (?preview)
- Any `?preview` on `/`, `/news`, `/news/[id]` includes `draft`/`pending_review` stories in the feed and enables click-through to draft detail pages (bare `?preview` also works; `0`/`false` disable; card links normalize to `?preview=1`); a preview banner is shown. Detail router owns DB sourcePostIds: an unpublished story's id 404s without preview (no legacy JSON fallback).
- Production: preview is **completely disabled** — unpublished stories can never be loaded via query params in a prod build (dev-only feature). Review for publish happens via `editorial:pending`; publish applies the gates.
- `/news/[id]` passes `includeDrafts=true` only in preview mode; `getPublishedStoryByNumericId(id, includeDrafts)` is the shared lookup. Gated by `lib/preview.ts::previewValue`.

### Genus pages & fossil maps
- `/genus/[slug]` renders a Natural Earth (d3-geo) map of fossil find locations when `genus.meta.fossilLocations` is non-empty, with pan/zoom, progressive coastline detail (110m→50m→10m), US/global sub-country borders on zoom, zoom buttons, and keyboard accessibility. Map dots are colored by geologic period (Mesozoic Era page colors). Below the map: a geologic time bar (`components/GeologicTimeBar.tsx`) showing Mesozoic periods/epochs with occurrence ages. Plus a text list of localities and a PBDB link. Data: `npm run enrich:locations`.
- `npm run enrich:locations` (`scripts/enrich-genus-locations.ts`) populates `meta.fossilLocations` on every genus in `_data/genus-data.json` from the Paleobiology Database (PBDB `occs/list.json`, `show=loc,coords`). Queried by **`base_name`**, not `taxon_name` — occurrences are mostly identified to species, so `taxon_name` matched only 335/1,550 genera vs. 1,461 with `base_name`. Taxon names are normalised before the request (wrapping quotes/punctuation stripped, diacritics folded) because PBDB rejects e.g. `“Gspsaurus”`/`Troödon` with HTTP 400. Occurrences are aggregated into ~0.5° bubbles (top 60 per genus). Per-taxon results are cached in `_data/pbdb-cache.json` (gitignored, resumable, entries tagged `CACHE_VERSION` — bump it when the query or aggregation changes); `--limit N`, `--genus <Name>`, `--force` supported. Genera with no PBDB records are left untouched (no map section, no placeholder), and a transport failure is never cached as "has no fossils".
